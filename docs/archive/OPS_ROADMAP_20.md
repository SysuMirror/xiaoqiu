> 上位纲领：全站/全服务器运维 100% 依赖小秋 Ops，完全替代传统运维。
> 硬约束：唯一面板账号 2215020897@qq.com；鉴权固定对接后端 OAuth 体系（禁改后端链路）；保留画布与模块-代码核心绑定；允许全链路重构或新建前端目录。
> 每轮闭环五步：定问题/约束/量化目标 → 三方案调研选型 → 业务定制 → 架构落地 → 风险兜底。
> 里程碑：R5 后首份 1000 字评估；R10 后第一次全量生产化；R15 后第二份评估；R20 后第二次生产化 + 最终复盘 + 长期运维方案。

| 轮 | 方向 | 维度 | 核心交付（量化目标） |
|---|---|---|---|
| **R1** | 面板鉴权与账号体系 | 权限体系① | 对接后端 OAuth/登录链路；/ops/* 全端点鉴权；公网可访问（去隧道）；登录限流+单账号白名单 |
| **R2** | 流量分析台账 | 流量监控① | 接口级 RED 时序存储（不只差分瞬时值）；TOP 榜/趋势图；窗口可切换（30m/6h/24h） |
| **R3** | 错误捕获与指纹聚类 | 错误排查① | 5xx 样本留存（路由/状态/时间）；错误指纹去重统计（首末次/次数/影响面）；错误下钻视图 |
| **R4** | 全链路请求追踪 | 故障溯源① | request_id 从 nginx→Go→DB 贯穿；单请求时间线视图；慢请求 TopN 溯源 |
| **R5** | 可视化基座升级 | 可视化运维① | 时序图/热力图/TopN 组件统一（图表基座 + 暗色一致）；首份 1000 字使用者评估报告 |
| **R6** | 告警规则引擎 | 自动化运维① | 告警规则 CRUD（阈值/持续/静默窗口）；分级（info/warn/critical）；通知路由（邮件+面板通知中心） |
| **R7** | 安全动作链与审批流 | 自动化运维② | L1 只读动作面板化（日志拉取/配置快照）；L2 智能诊断一键化；L3 破坏性动作 OAuth 账号二次审批 |
| **R8** | 前端工程化重构 | 架构优化① | 新建独立前端目录（组件化/构建管线）；G6 画布与模块绑定核心原样迁移；加载性能基线 |
| **R9** | Agent 自身高可用 | 生产稳定性① | 多 worker/优雅重启；依赖断路器面板化；自监控（agent 自身指标上图） |
| **R10** | 【第一次全量生产化】 | 生产稳定性①+ | 架构收敛+性能优化+安全加固+容灾（备份/恢复演练）；阶段评估报告 |
| **R11** | 存储容量治理 | 弹性扩容① | 数据保留策略（TTL/分区/降精度采样）；存储增长可预测；大盘窗口不受数据量影响 |
| **R12** | 开放标准互操作 | 架构优化② | /metrics Prometheus 完全兼容（可被外部采集）；Grafana 导入配置；API 开放契约文档 |
| **R13** | AI 归因升级 | 故障溯源② | 签名未命中→LLM 假设生成+工具验证闭环（P3 归因）；归因置信度标注；误报反馈回路 |
